# local-router

작업을 받으면 먼저 분류한다. 기준은 **작고, 독립적이고, 틀려도 바로 알아챌 수 있는가**이다.

## 로컬로 보낸다 (전부 해당할 때)
- 한 함수·한 스니펫 안에서 끝나고, 필요한 코드를 지시에 모두 붙여 넣을 수 있다.
- 결과를 내가 읽거나 실행해서 바로 검증할 수 있다.
- 예: 함수 하나 작성, 20~50줄 코드 설명, 정규식·SQL·셸 한 줄, 커밋 메시지 초안, 독스트링·주석 추가, 형식 변환(JSON↔YAML 등), 짧은 글(약 1만 자 이하) 요약.

## Claude가 직접 한다 (하나라도 해당하면)
- 여러 파일을 읽거나 고쳐야 한다. 저장소 전체 맥락이 필요하다.
- 보안, 인증, 결제, 데이터 삭제와 관련 있다.
- 원인을 모르는 버그 디버깅, 설계·리팩터링 방향 결정.
- 도구(파일 수정, 명령 실행)를 써야 하는 작업.
- 비밀번호, 키, 개인정보가 들어 있다. (로컬은 외부로 나가지 않아 안전하지만, 작은 모델이 이런 작업을 잘못 처리하기 쉬워서 직접 한다.)
- 판단이 애매하면 직접 한다.

## 로컬로 보내는 방법
이 스킬의 폴더(스킬을 불러올 때 표시된 Base directory)에 있는 `local.py`를 쓴다. Windows에서 `python`이 종료 코드 49와 "Python"만 출력하면(Microsoft Store 안내) 설치되지 않은 것이니 `uv run --no-project python -I`로 바꾼다. 처음부터 `uv`가 있으면 그것을 쓴다.

```bash
python <Base directory>/local.py "지시 한 줄"              # 짧은 지시
cat 파일.py | python <Base directory>/local.py --stdin "이 코드를 설명해줘"   # 코드는 --stdin 으로
python <Base directory>/local.py --test                    # 연결 점검
```
기본 모델은 `qwen2.5-coder:3b`이다. 더 어려우면 `--model qwen2.5-coder:7b`(느림)를 쓸 수 있다.

## 받은 결과는 반드시 검증한다
1. 코드면 읽어서 맞는지 보고, 가능하면 실행하거나 짧은 테스트로 확인한다.
2. 틀렸거나 엉뚱하면 **같은 지시를 한 번 더 보내지 말고** Claude가 직접 처리한다.
3. `local.py`가 실패(종료 코드 1)하면 Ollama가 꺼져 있다는 뜻이니 직접 처리한다.

## 사용자에게 알린다
답변 끝에 한 줄로 어느 쪽이 처리했는지 적는다. 예: "로컬 3B가 작성, Claude가 검증" 또는 "범위가 넓어서 Claude가 직접 처리".

## 한계
- 측정 결과(이 PC, 3B): 작은 작업에서는 로컬로 보내는 쪽이 오히려 더 느리고 더 비쌌다. 로컬 초안이 틀려 Claude가 다시 쓰는 경우도 있었다. 그래서 사용자가 요청할 때만 쓴다.
- 분류는 이 지침을 읽은 Claude의 판단이라 항상 맞는다는 보장이 없다.
- 지시를 쓰고 결과를 검증하는 데도 Claude 토큰이 든다. 아주 작은 작업은 직접 하는 편이 더 싸다.
- 로컬 3B는 한국어와 복잡한 요구에 약하다. 한국어 지시보다 영어 지시가 정확한 경우가 많다.
